# Техническое задание

## Веб-приложение «Планировщик приёмов и увольнений»

**Версия документа:** 1.0  
**Язык интерфейса:** русский  
**Тип приложения:** одностраничное клиентское веб-приложение  
**Целевой пользователь:** кадровик

---

## 1. Цель продукта

Приложение предназначено для планирования будущих приёмов и увольнений сотрудников, просмотра кадровых событий в календаре и таблице, а также фиксации результата события после его наступления.

Приложение не использует сервер, базу данных и авторизацию. Все пользовательские записи и настройки хранятся в `localStorage` текущего браузера.

## 2. Состав проекта и ограничения реализации

Проект должен состоять ровно из трёх прикладных файлов:

- `index.html` — семантическая HTML-разметка;
- `style.css` — стили и адаптивная вёрстка;
- `script.js` — данные, состояние, бизнес-логика и работа с `localStorage`.

Требования:

- приложение запускается открытием `index.html` в браузере;
- для основной логики используется чистый JavaScript без фреймворков;
- разрешено подключать через CDN вспомогательную библиотеку календаря и веб-шрифт;
- согласно требованию заказчика, штатный режим предполагает наличие интернета;
- потеря интернета после загрузки страницы не должна повреждать данные;
- интерфейс должен работать в актуальных версиях Chrome, Edge, Firefox и Safari, включая мобильные версии;
- поддержка устаревших браузеров, включая Internet Explorer, не требуется;
- зависимости не должны требовать сборки, npm или локального сервера.

Если календарь реализуется библиотекой, следует использовать FullCalendar через CDN. При невозможности загрузить библиотеку пользователю выводится понятное сообщение, а таблица и операции с записями продолжают работать.

## 3. Термины и ключевое проектное решение

**Кадровое событие** — отдельная запись одного из двух типов: «Приём» или «Увольнение».

Каждый приём и каждое увольнение создаются отдельными записями. Одна запись не должна одновременно обозначать оба события. Если для одного сотрудника требуется запланировать приём и увольнение, кадровик создаёт две записи. В календаре и таблице каждая из них отображается отдельно по собственной дате события.

В интерфейсе используется единое поле «Дата события». Для записи «Приём» оно подписывается «Дата приёма», для записи «Увольнение» — «Дата увольнения». Это устраняет неоднозначность исходного перечня полей.

## 4. Роль и права пользователя

В продукте существует одна роль — кадровик. Кадровик может:

- просматривать календарь и таблицу событий;
- выбирать произвольный период;
- переключать отображение между всеми событиями, приёмами и увольнениями;
- создавать приёмы и увольнения;
- просматривать полную запись;
- редактировать запись;
- дублировать запись;
- удалять запись и отменять только что выполненное удаление;
- вручную менять статус события;
- вводить комментарий при фиксации результата;
- выбирать должность и подразделение из неизменяемых справочников.

Пользователь не может:

- редактировать справочники;
- создавать собственные статусы;
- импортировать или экспортировать данные;
- управлять пользователями;
- синхронизировать сведения с другими устройствами.

## 5. Модель данных

### 5.1. Объект кадрового события

Каждая запись в `localStorage` имеет следующий формат:

```js
{
  id: "uuid-string",
  eventType: "hire" | "dismissal",
  fullName: "Иванов Иван Иванович",
  position: "Должность 1",
  department: "Подразделение 1",
  eventDate: "2026-08-19",
  rate: 1,
  status: "Прием" | "Принят" | "Отменён" | "Нет документов" | "Не пришёл" |
          "Увольнение" | "Уволен",
  comment: "",
  createdAt: "2026-08-19T10:00:00.000Z",
  updatedAt: "2026-08-19T10:00:00.000Z"
}
```

Правила хранения:

- `id` уникален; предпочтительно `crypto.randomUUID()`, с безопасным резервным генератором;
- `eventDate` хранится как локальная календарная дата `YYYY-MM-DD`, без преобразования в UTC;
- `rate` хранится числом;
- технические поля `createdAt` и `updatedAt` хранятся, но не показываются пользователю;
- пустой комментарий хранится как пустая строка;
- неизвестные поля при чтении игнорируются.

### 5.2. Формат хранилища

Ключ данных: `hrPlannerData`. Значение:

```js
{
  version: 1,
  records: []
}
```

Ключ настроек: `hrPlannerSettings`. Значение:

```js
{
  periodStart: "2026-08-17",
  periodEnd: "2026-08-23",
  activeTypeFilter: "all",
  calendarDate: "2026-08-19"
}
```

Все изменения записей и настроек сохраняются немедленно. Даты периода и активный фильтр восстанавливаются после перезагрузки.

### 5.3. Справочники

Подразделения:

1. Подразделение 1
2. Подразделение 2
3. Подразделение 3
4. Подразделение 4
5. Подразделение 5
6. Подразделение 6

Должности:

1. Должность 1
2. Должность 2
3. Должность 3
4. Должность 4

Списки задаются константами в `script.js`. Любая должность совместима с любым подразделением. В форме применяются элементы `select`; свободный ввод и значение «Другое» отсутствуют. Если сохранённое значение отсутствует в справочнике, запись можно просмотреть, но при редактировании требуется выбрать допустимое значение.

## 6. Статусы и переходы

### 6.1. Приём

- `Прием` — начальный статус запланированного приёма;
- `Принят` — сотрудник принят;
- `Отменён` — приём отменён;
- `Нет документов` — событие не завершено из-за отсутствия документов;
- `Не пришёл` — кандидат не явился.

### 6.2. Увольнение

- `Увольнение` — начальный статус запланированного увольнения;
- `Уволен` — сотрудник уволен;
- `Отменён` — увольнение отменено.

### 6.3. Правила смены статуса

- статус меняет только кадровик; автоматических переходов по дате нет;
- при создании статус назначается автоматически: `Прием` или `Увольнение`;
- начальный статус нельзя выбрать в форме создания;
- после сохранения кадровик может выбрать любой статус, разрешённый для данного типа события;
- обратные переходы разрешены, чтобы кадровик мог исправить ошибку;
- статус одного типа нельзя присвоить событию другого типа;
- при смене типа события во время редактирования статус сбрасывается в начальный статус нового типа после подтверждения пользователя;
- при выборе итогового или проблемного статуса открывается поле комментария; комментарий необязателен;
- статус и комментарий могут быть изменены до, в день и после даты события.

## 7. Структура основного экрана

Порядок блоков:

1. Шапка с названием приложения.
2. Две основные кнопки: «Запланировать приём» и «Запланировать увольнение».
3. Панель выбора периода: «Дата с», «Дата по», кнопка «Текущая неделя».
4. Сводные интерактивные карточки «Приёмы» и «Увольнения».
5. Месячный календарь.
6. Таблица событий выбранного периода.
7. Контейнер уведомлений.
8. Модальные окна.

В шапке или рядом со сводкой должен быть доступен элемент «Показать все», снимающий фильтр по типу события.

## 8. Выбранный период

- при первом запуске устанавливается текущая неделя с понедельника по воскресенье;
- текущая дата включается в период;
- пользователь может выбрать любой диапазон без ограничения длины;
- обе границы периода включаются;
- дата начала не может быть позже даты окончания;
- при ошибочном диапазоне выводится сообщение, отображение не обновляется;
- изменение периода обновляет сводку и таблицу;
- выбранный период сохраняется в настройках;
- календарь остаётся месячной сеткой и использует собственную навигацию, но при выборе периода переходит к месяцу даты начала;
- выбор месяца в календаре не изменяет заданный диапазон таблицы и сводки;
- кнопка «Текущая неделя» сбрасывает диапазон на текущую неделю.

## 9. Сводная панель и фильтрация

Карточки показывают количество записей соответствующего типа в выбранном периоде:

- «Приёмы» — все записи типа `hire`, включая завершённые, проблемные и отменённые;
- «Увольнения» — все записи типа `dismissal`, включая завершённые и отменённые.

Показатели являются счётчиками событий, а не прогнозом численности. Отдельные показатели по статусам не нужны.

Поведение:

- нажатие на «Приёмы» включает фильтр `hire` для календаря и таблицы;
- нажатие на «Увольнения» включает фильтр `dismissal`;
- нажатие на уже активную карточку снимает фильтр и показывает все события;
- элемент «Показать все» также снимает фильтр;
- активная карточка имеет визуально заметное состояние и `aria-pressed="true"`;
- фильтр сохраняется после перезагрузки;
- числа на карточках всегда отражают полный выбранный период и не меняются из-за активного фильтра.

## 10. Календарь

### 10.1. Представление

- полноценная месячная сетка;
- неделя начинается с понедельника;
- названия месяцев и дней недели на русском;
- кнопки «Предыдущий месяц», «Сегодня», «Следующий месяц»;
- заголовок содержит месяц и год;
- отображаются события месяца с учётом активного фильтра по типу;
- выбранный произвольный период не скрывает события календарного месяца, поскольку календарь служит отдельным навигационным представлением;
- текущий день выделяется;
- отменённые события имеют приглушённый вид и зачёркнутую подпись.

### 10.2. Содержание события

В элементе события показываются:

- ФИО;
- тип: «Приём» или «Увольнение»;
- статус.

Приём обозначается мятным акцентом, увольнение — белым/серым контрастным акцентом на чёрном фоне. Проблемные статусы получают предупреждающий акцент, отменённые — нейтральный серый. Смысл всегда дублируется текстом.

### 10.3. Большое число событий

В ячейке показываются первые три события. Остальные сворачиваются в ссылку «Ещё N». Нажатие открывает модальное окно со списком всех событий выбранного дня.

### 10.4. Действия

- нажатие на событие открывает режим просмотра записи;
- нажатие на пустую область даты открывает небольшой выбор «Запланировать приём» / «Запланировать увольнение» и подставляет выбранную дату;
- нажатие на «Ещё N» показывает список дня;
- клавиатурное нажатие `Enter` или `Space` выполняет то же действие, что щелчок.

## 11. Таблица событий

Таблица содержит столбцы:

1. Дата события.
2. Кадровое событие.
3. ФИО.
4. Должность.
5. Подразделение.
6. Ставка.
7. Статус.
8. Комментарий.
9. Действия.

Правила:

- показываются записи, дата которых входит в выбранный период;
- применяется активный фильтр «Все» / «Приёмы» / «Увольнения»;
- записи сортируются по дате по возрастанию, при одинаковой дате — по ФИО через русскую локаль;
- пользовательский поиск, сортировка по столбцам и дополнительные фильтры отсутствуют;
- комментарий отображается полностью с переносом строк;
- в пустой таблице тело остаётся пустым, без отдельного текста-заглушки;
- заголовки таблицы остаются видимыми;
- строка открывается для просмотра кликом, но интерактивные элементы внутри строки работают независимо.

В столбце действий находятся кнопки с текстом или доступными подписями: «Просмотреть», «Изменить», «Дублировать», «Удалить». Статус меняется через компактный `select` в строке.

На экранах уже `768 px` каждая строка преобразуется в карточку со всеми полями и действиями. Горизонтальная прокрутка не должна быть основным способом использования.

## 12. Модальные окна

Используются следующие окна:

- создание приёма;
- создание увольнения;
- просмотр записи;
- редактирование записи;
- список событий дня;
- подтверждение удаления;
- подтверждение выхода с несохранёнными изменениями;
- подтверждение смены типа события;
- сообщение о повреждённом хранилище.

Общие требования:

- фон страницы блокируется;
- фокус переводится внутрь окна и удерживается в нём;
- `Escape` закрывает окно, если нет несохранённых изменений;
- кнопка закрытия имеет доступное название;
- после закрытия фокус возвращается на элемент, открывший окно;
- на телефоне окно занимает почти всю ширину, содержимое прокручивается внутри;
- одновременно открыто только одно основное модальное окно; подтверждение может отображаться поверх него.

## 13. Создание записи

### 13.1. Точки входа

- кнопка «Запланировать приём»;
- кнопка «Запланировать увольнение»;
- выбор действия на дате календаря;
- дублирование существующей записи.

### 13.2. Поля формы

- «Кадровое событие» — предустановлено точкой входа, допускается переключение;
- «ФИО» — текстовое поле;
- «Должность» — обязательный список;
- «Подразделение» — обязательный список;
- «Дата приёма» или «Дата увольнения» — обязательная дата;
- «Ставка» — обязательное числовое поле;
- статус показывается как нередактируемое значение начального статуса;
- комментарий при создании не показывается и сохраняется пустым.

### 13.3. Успешное сохранение

- создаётся объект с новым `id`;
- данные сохраняются в `localStorage`;
- календарь, сводка и таблица обновляются;
- модальное окно закрывается;
- появляется уведомление «Событие сохранено»;
- уведомление исчезает через 4 секунды и доступно экранному диктору через `aria-live="polite"`.

## 14. Просмотр и редактирование

Режим просмотра является отдельным, только для чтения. Он показывает все пользовательские поля и кнопки «Изменить», «Дублировать», «Удалить», «Закрыть».

В режиме редактирования доступны все поля, включая статус и комментарий. Сохранение возможно только после проверки. При закрытии изменённой формы без сохранения показывается подтверждение:

> Есть несохранённые изменения. Закрыть форму и потерять изменения?

Если изменений нет, форма закрывается сразу.

Смена типа события:

- требует подтверждения;
- меняет подпись даты;
- сбрасывает статус на `Прием` или `Увольнение`;
- сохраняет остальные поля и комментарий;
- после отмены подтверждения тип и статус остаются прежними.

## 15. Быстрая смена статуса

- выполняется из таблицы либо из режима просмотра;
- список содержит только статусы данного типа события;
- изменение сохраняется немедленно;
- если выбран статус, отличный от начального, открывается компактная форма комментария с кнопками «Сохранить» и «Без комментария»;
- закрытие формы комментария без выбора отменяет смену статуса;
- после успеха все представления обновляются и показывается уведомление;
- автоматической смены статуса нет.

## 16. Дублирование

Дублирование открывает форму создания, заполненную данными исходной записи.

- тип, ФИО, должность, подразделение и ставка копируются;
- дата очищается и обязательна для повторного ввода;
- статус сбрасывается на начальный;
- комментарий очищается;
- новый объект не создаётся до нажатия «Сохранить»;
- используется новый `id` и новые технические даты.

Такой порядок предотвращает случайное создание точного дубликата.

## 17. Удаление и отмена удаления

Перед удалением показывается подтверждение с ФИО, типом и датой события. Основная кнопка имеет текст «Удалить», безопасная — «Отмена».

После удаления:

- запись удаляется из хранилища и всех представлений;
- в течение 7 секунд показывается уведомление «Запись удалена» с кнопкой «Отменить»;
- отмена восстанавливает запись с тем же `id` и данными;
- при удалении следующей записи предыдущая возможность отмены завершается;
- после истечения 7 секунд восстановление через интерфейс невозможно.

## 18. Валидация

### 18.1. Обязательные поля

Для обоих типов обязательны:

- тип события;
- ФИО;
- должность;
- подразделение;
- дата события;
- ставка.

Статус назначается системой. Комментарий необязателен.

### 18.2. ФИО

- пробелы в начале и конце удаляются;
- повторяющиеся внутренние пробелы заменяются одним;
- пустая после нормализации строка запрещена;
- ограничение длины не устанавливается;
- цифры и специальные символы не блокируются, чтобы не исключать редкие корректные имена, но поле должно содержать хотя бы одну букву;
- HTML из пользовательского ввода никогда не вставляется через `innerHTML`; вывод осуществляется безопасно через `textContent`.

### 18.3. Дата

- текущая дата разрешена;
- прошедшая дата запрещена при создании, включая дублирование;
- при редактировании существующей записи прошедшая дата допустима, если она не изменялась;
- заменить дату на другую прошедшую дату нельзя;
- остальные поля и статус прошлой записи редактировать можно;
- сравнение выполняется по локальной календарной дате без времени и UTC-сдвигов.

### 18.4. Ставка

- допустимое значение: от `0,01` до `1` включительно;
- дробный разделитель при вводе может быть запятой или точкой;
- после разбора хранится число с точкой;
- шаг поля — `0.01`;
- ноль, отрицательные значения, значения больше `1`, `NaN` и пустое поле запрещены;
- при выводе используется русская запись без лишних конечных нулей: `1`, `0,5`, `0,25`.

### 18.5. Дубликаты

Точным дубликатом считается другая запись с совпадающими:

- нормализованным ФИО;
- типом события;
- датой события.

Для сравнения ФИО игнорируются регистр, пробелы по краям, повторяющиеся пробелы и различие `Е/Ё`.

Точный дубликат запрещён: форма не сохраняется и показывает сообщение «Такое кадровое событие уже существует». Совпадение только ФИО не является ошибкой и не требует подтверждения.

### 18.6. Отображение ошибок

- ошибка показывается под соответствующим полем;
- поле получает визуальное состояние ошибки и `aria-invalid="true"`;
- сверху формы выводится краткое сообщение «Проверьте заполнение полей»;
- при неуспешной отправке фокус переводится на первое ошибочное поле;
- текст ошибки объясняет способ исправления;
- ошибки снимаются после корректировки значения.

## 19. Работа с `localStorage` и ошибки хранения

### 19.1. Чтение

- отсутствие ключа означает первый запуск и пустой список;
- данные проверяются на корректный JSON, версию и массив записей;
- отдельные некорректные записи пропускаются, корректные загружаются;
- если корневой объект повреждён, приложение не перезаписывает его автоматически.

Пользователю показывается окно:

> Не удалось прочитать сохранённые данные. Можно очистить повреждённые данные и начать заново.

Доступны «Очистить и продолжить» и «Повторить загрузку». Очистка выполняется только после подтверждения.

### 19.2. Запись

- операции с памятью выполняются только после успешной записи в `localStorage`;
- при переполнении или запрете хранилища изменение откатывается;
- выводится сообщение «Не удалось сохранить данные в браузере»;
- приложение не должно показывать несохранённые изменения как успешно сохранённые.

### 19.3. Несколько вкладок

Приложение слушает событие `storage`. При изменении данных в другой вкладке список автоматически перечитывается и все представления обновляются. Если в текущей вкладке открыта изменённая форма, автоматическое обновление откладывается и показывается предупреждение с предложением перезагрузить данные после сохранения или отмены изменений.

Ограничение количества записей не вводится. Ошибка квоты обрабатывается по общему правилу ошибки сохранения.

## 20. Сценарии использования

### UC-01. Первый запуск

1. Кадровик открывает `index.html`.
2. Приложение загружает пустое хранилище.
3. Период устанавливается на текущую неделю.
4. Счётчики равны нулю, календарь не содержит событий, тело таблицы пустое.

**Результат:** приложение готово к созданию первой записи.

### UC-02. Создание приёма

1. Кадровик нажимает «Запланировать приём».
2. Открывается форма с типом «Приём» и статусом «Прием».
3. Кадровик заполняет обязательные поля.
4. Приложение проверяет дату, ставку, справочники и дубликат.
5. Кадровик нажимает «Сохранить».

**Результат:** запись сохраняется и появляется в календаре, таблице и счётчике приёмов.

### UC-03. Создание увольнения

Аналогично UC-02, но используется тип «Увольнение», поле «Дата увольнения» и начальный статус «Увольнение».

### UC-04. Создание события из календаря

1. Кадровик нажимает на дату.
2. Выбирает приём или увольнение.
3. Открывается форма с подставленной датой.
4. Заполняет данные и сохраняет.

**Результат:** создаётся событие выбранного типа на выбранную дату.

### UC-05. Ошибка обязательного поля

1. Кадровик оставляет обязательное поле пустым.
2. Нажимает «Сохранить».
3. Приложение не закрывает форму, показывает ошибку и переводит фокус.

**Результат:** некорректная запись не создана.

### UC-06. Запрет прошедшей даты

1. Кадровик создаёт запись с датой раньше текущей.
2. Приложение показывает ошибку даты.

**Результат:** запись не сохраняется до выбора текущей или будущей даты.

### UC-07. Запрет дубликата

1. Кадровик вводит ФИО, тип и дату уже существующего события.
2. Приложение обнаруживает точный дубликат.

**Результат:** сохранение запрещено, существующая запись не меняется.

### UC-08. Просмотр события

1. Кадровик нажимает строку таблицы или событие календаря.
2. Открывается окно только для чтения.

**Результат:** видны все данные и доступные действия.

### UC-09. Редактирование

1. Кадровик открывает запись и нажимает «Изменить».
2. Меняет допустимые поля.
3. Нажимает «Сохранить».

**Результат:** данные проверяются, сохраняются и обновляются во всех представлениях.

### UC-10. Закрытие изменённой формы

1. Кадровик меняет поле и пытается закрыть форму.
2. Приложение предупреждает о несохранённых изменениях.
3. Кадровик продолжает редактирование либо подтверждает выход.

**Результат:** данные не теряются без явного подтверждения.

### UC-11. Фиксация результата

1. Кадровик меняет статус приёма или увольнения.
2. При необходимости вводит комментарий.
3. Подтверждает изменение.

**Результат:** новый статус и комментарий сохраняются и отображаются в календаре и таблице.

### UC-12. Дублирование

1. Кадровик нажимает «Дублировать».
2. Открывается предзаполненная форма с пустой датой, начальным статусом и пустым комментарием.
3. Кадровик задаёт дату и сохраняет.

**Результат:** создаётся независимая запись с новым идентификатором.

### UC-13. Удаление

1. Кадровик нажимает «Удалить».
2. Проверяет ФИО, тип и дату в подтверждении.
3. Подтверждает удаление.

**Результат:** запись удалена, показана кнопка отмены на 7 секунд.

### UC-14. Отмена удаления

1. После удаления кадровик нажимает «Отменить» в уведомлении.

**Результат:** запись восстановлена во всех представлениях.

### UC-15. Выбор периода

1. Кадровик задаёт начальную и конечную даты.
2. Приложение проверяет порядок дат.

**Результат:** таблица и счётчики показывают события включительно за выбранный период; настройка сохранена.

### UC-16. Фильтр по типу

1. Кадровик нажимает карточку «Приёмы» или «Увольнения».

**Результат:** календарь и таблица показывают выбранный тип; повторное нажатие снимает фильтр.

### UC-17. Навигация календаря

1. Кадровик переключает месяц кнопками назад/вперёд или возвращается к текущему месяцу.

**Результат:** календарь показывает выбранный месяц; период таблицы не меняется.

### UC-18. Несколько событий в день

1. В ячейке больше трёх событий.
2. Кадровик нажимает «Ещё N».

**Результат:** открывается полный список событий дня с возможностью просмотреть каждое.

### UC-19. Работа с прошлой записью

1. Дата сохранённого события наступила или прошла.
2. Кадровик выбирает прошлый период.
3. Открывает запись, меняет статус или комментарий.

**Результат:** запись остаётся доступной; изменить её дату на другую прошлую нельзя.

### UC-20. Изменение данных в другой вкладке

1. В другой вкладке изменяется хранилище.
2. Если текущая форма не изменена, приложение автоматически обновляется.
3. Если есть несохранённые изменения, выводится предупреждение.

**Результат:** данные вкладок согласуются без скрытой потери введённых сведений.

### UC-21. Ошибка хранилища

1. Чтение или запись `localStorage` завершается ошибкой.
2. Приложение показывает понятное сообщение и не сообщает об успешном сохранении.

**Результат:** пользователь понимает состояние данных, повреждённые данные не удаляются без подтверждения.

## 22. Адаптивность

Контрольные диапазоны:

- от `320 px` до `767 px` — мобильный интерфейс;
- от `768 px` до `1199 px` — планшет/небольшой экран;
- от `1200 px` — широкий экран.

Требования:

- отсутствие горизонтального скролла страницы при ширине `320 px`;
- кнопки и поля имеют область нажатия не менее `44 × 44 px`;
- основные кнопки на телефоне могут занимать всю ширину;
- сводные карточки располагаются в две колонки, а на очень узком экране — в одну;
- таблица превращается в карточки;
- календарь допускает сокращённые подписи и компактные события;
- модальные окна не выходят за границы экрана;
- контент остаётся читаемым при масштабировании до 200%.

## 23. Доступность

- семантические `header`, `main`, `section`, `table`, `button`, `form`;
- у каждого поля есть связанный `label`;
- интерфейс полностью доступен с клавиатуры;
- видимый индикатор фокуса;
- логичный порядок `Tab`;
- интерактивные карточки реализуются кнопками, а не `div` с обработчиком;
- модальные окна используют `role="dialog"`, `aria-modal="true"` и заголовок;
- ошибки связаны с полями через `aria-describedby`;
- уведомления используют `aria-live`;
- цвет не является единственным признаком типа, статуса или ошибки;
- контраст обычного текста не ниже 4.5:1;
- анимации сокращаются при `prefers-reduced-motion`.

## 28. Критерии приёмки

Продукт принят, если одновременно выполняются условия:

- присутствуют только требуемые три прикладных файла, и они корректно связаны;
- приложение открывается без сервера;
- кадровик может создать отдельные записи приёма и увольнения;
- все поля, справочники, статусы и ограничения соответствуют этому ТЗ;
- данные сохраняются в `localStorage` и восстанавливаются после перезагрузки;
- текущая неделя используется как начальный период и выбранный период запоминается;
- сводные карточки считают и фильтруют события;
- календарь является месячной сеткой с русской локалью и навигацией;
- таблица содержит все поля и сортируется по ближайшей дате;
- просмотр, редактирование, дублирование, удаление, отмена удаления и быстрая смена статуса работают;
- прошлые даты запрещены при создании, но прошлые записи сохраняются и доступны;
- точные дубликаты блокируются;
- ошибки формы понятны и не приводят к частичному сохранению;
- интерфейс пригоден для компьютера и телефона шириной от 320 px;
- основные действия доступны с клавиатуры;
- пользовательские данные выводятся безопасно;
- отсутствие CDN-календаря не лишает пользователя доступа к таблице и данным;
- в консоли нет необработанных ошибок при штатных сценариях.
